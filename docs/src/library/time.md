# cdt.time

The `cdt.time` standard library provides system and monotonic clock operations, duration arithmetic, and UTC Unix epoch conversions.

```conduit
import cdt.time as time
```

---

## Conceptual Overview

### System Time vs. Monotonic Time

Conduit maintains a strict distinction between wall-clock system time and monotonic measurement time:

1. **`time.Timestamp` (System Clock)**
   - Measured via `time.now()`.
   - Represents a specific point on the human calendar.
   - Used for logging events, database timestamps, and Unix epoch conversion.
   - May change or jump if the host system clock is updated or synchronized via NTP.

2. **`time.Instant` (Monotonic Clock)**
   - Measured via `time.monotonic()`.
   - Guaranteed to never jump backwards, even during NTP adjustments or leap seconds.
   - Exclusively used for measuring elapsed intervals, benchmarking, and timeouts via `time.elapsed(start)`.

3. **`time.Duration` (Time Span)**
   - Represents a non-negative duration of time.
   - Constructed using `time.seconds(n)` or `time.milliseconds(n)`.
   - Created automatically when calculating `time.elapsed(instant)`.
   - Cannot represent negative spans. Attempting to construct a negative duration returns a `time.TimeError`.

## API Reference

### Types

#### Duration
- **Qualified Name:** `time.Duration`
- **Category:** Opaque Type
- **Description:** Non-negative time span representation

#### Instant
- **Qualified Name:** `time.Instant`
- **Category:** Opaque Type
- **Description:** Monotonically increasing clock measurement point for benchmarks and elapsed timing

#### TimeError
- **Qualified Name:** `time.TimeError`
- **Category:** Error Type
- **Description:** Error occurring during time operations (overflow, negative duration, invalid order)
- **Fields:**
  - `message: String`

#### Timestamp
- **Qualified Name:** `time.Timestamp`
- **Category:** Opaque Type
- **Description:** Moment of system time measured from the system clock
